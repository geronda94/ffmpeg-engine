# Руководство по JSON-конфигурации (v2.0)

Этот документ описывает структуру и логику интерпретации JSON-файлов нашим движком монтажа.

## Общая структура
Конфиг состоит из 6 основных блоков:
1. `output`: Параметры итогового файла.
2. `resources`: Список исходных материалов (входы).
3. `presets`: Шаблоны эффектов (многократное использование).
4. `pipeline`: Индивидуальная обработка каждого фрагмента.
5. `compose`: Схема наложения слоев друг на друга.
6. `audio`: Настройки звуковой дорожки.

---

## 1. Resources (Ресурсы)
Движок поддерживает три типа источников:
- **Локальные файлы**: путь к файлу на диске (например, `local_assets/img.jpg`).
- **URL**: прямые ссылки на картинки/видео. Движок скачает их в `temp_render` и удалит после работы.
- **LAVFI**: внутренние генераторы FFmpeg (например, `color=c=black:s=540x960` для создания фонового холста).

```json
{ "id": "my_img", "source": "https://example.com/image.jpg", "type": "image" }
```

---

## 2. Presets (Пресеты)
Пресеты позволяют избежать дублирования кода. Вы описываете набор `actions`, а затем просто ссылаетесь на них в `pipeline`.
**Важно**: Если в шаге пайплайна указаны и `preset`, и свои `actions`, то сначала выполнятся действия из пресета, а затем ваши локальные.

---

## 3. Pipeline (Обработка)
Здесь происходит магия подготовки фрагмента. Каждый объект в `pipeline` — это отдельный видеопоток.

### Основные поля:
- `id`: уникальное имя потока (используется позже в `compose`).
- `input`: id ресурса.
- `trim`: обрезка. Поля `start` и `end` задают границы фрагмента в **абсолютном** времени исходника.
- `actions`: список эффектов.

### Как интерпретируются Actions:
1. **Геометрия (`scale`, `scale_and_crop`, `scale_contain`)**: Приводят картинку к нужному размеру.
2. **Эффекты (`blur`, `drawtext`)**: Накладывают визуальные изменения.
   - `drawtext`: Если в `fontfile` передать URL (http/https), движок автоматически скачает шрифт и применит его.
3. **Время (`fade_in`, `fade_out`)**:
   - Время внутри секции `actions` всегда считается **от 0** (от начала вырезанного `trim` фрагмента).
   - `alpha: true|false` — если `true`, делает прозрачный кроссфейд (через формат `rgba`). Если `false`, уводит в сплошной цвет.
   - `color: "black"` — цвет затухания, если `alpha: false`.
4. **Анимация (`zoom`)**:
   - `zoom`: конечное значение масштаба (например, 1.4).
   - `smooth: true|false` — по умолчанию `true`. Включает трюк с 2x апскейлом для устранения дрожания (jitter). Выключите для ускорения рендера.
   - `expr`: произвольная математическая формула для FFmpeg фильтра `zoompan`. Позволяет делать сложные переходы. В формуле используйте переменную `on` (номер кадра, начиная с 1). Пример: `"expr": "if(gt(on, 330), 1+(on-330)*(0.4/45), 1)"` — линейный зум начнется только с 330-го кадра.

---

## 4. Compose (Композиция)
Здесь мы берем подготовленные в пайплайне фрагменты и «склеиваем» их.
- `base`: id фрагмента, который будет самым нижним слоем (обычно это черный холст).
- `layers`: список слоев, которые накладываются сверху по порядку.
- `pos`: координаты `x` и `y`. Поддерживаются формулы FFmpeg (например, `(W-w)/2`).

---

## 5. Audio (Звук)
- `source`: id аудио-ресурса.
- `fade_in` / `fade_out`: длительность затухания в секундах.
- Движок сам вычислит момент начала `fade_out`, основываясь на общей длительности видео.

---

## Нюансы интерпретации
1. **Изоляция сегментов**: Каждый фрагмент в пайплайне обрабатывается независимо со сбросом таймингов в 0. Отработавшие слои автоматически отключаются параметром `enable` при композиции, чтобы экономить память.
2. **Data-Driven подход**: Движок не содержит жестко закодированных эффектов. Вся магия (кроссфейды, кривые зума) должна описываться в JSON через `expr`, `alpha` и другие параметры.
3. **Авто-Cleanup**: Любой скачанный файл будет удален из временной папки `temp_render` по завершении сборки.
